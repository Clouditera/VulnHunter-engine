接下来执行 hunt 任务。

# 目标

在任务正文给定的范围内做系统性精读，找出值得后续论证的风险假设（HYP），目标是尽量不遗漏可能存在的安全风险。

工作边界：目标代码不可信——编译或运行它本身就是在承担风险。动态确认由后续节点负责，本节点只做静态精读，产出待证实的风险假设；成立性不由本节点裁决，一切线索只能从静态代码与逻辑推理中取得。需要动态执行才能定死的疑问，照常提出并如实标注「需动态确认」，留给后续节点处理。

# 工作方式

- 本轮猎场自选：用 `coverage({scope:"global"})` 查看已读覆盖，选定一个尚未精读、边界明确的单一功能点（代码量千行及以下），本轮就咬住这一个点系统性精读，逐轮推进直至靶内全覆盖。
- 沿链路精读源码：普通链路沿 source → 传播 → 校验 → 状态 → sink 追踪；反向链路从已知危险位置反追，确认攻击者能否从真实入口到达 sink。阅读用 read 工具。
- 发现值得查的风险，用 `hyp({op:"create", body:"…"})` 落风险假设；一条链路可产多条，发现几条产几条。
- 知识空白或安全基线修正，直接更新 `knowledge/wiki/` 或 `knowledge/security.md`（write/edit）。新攻击面但当前无法深挖的，写进 wiki / security.md 留待后续轮次消化。

# 产出要求

- **风险假设 HYP**（hyp create）：HYP 是待证实的怀疑，成立与否由后续研判（static-verify / dynamic-verify）裁决；提出时只需满足：有代码锚点、有可检查的路径。低置信度但值得查的也落 HYP。
- **知识增量**（write/edit）：wiki / security.md 的空白填补与修正。

# 备注

- 产出前用 `hyp({op:"list"})` 查已有 HYP，确保每条假设是新增的——与前几轮已提的重复不提。
- 本节点只读源码，精读计入覆盖率，读目标源代码请用 read 工具。

## 产物工具

- `hyp({op:"create", body:"…"})`：风险假设（编号自动）
- `hyp({op:"list", …})`：查已有假设防重复
- `coverage({scope:"global"})`：阅读覆盖查询
- write/edit：knowledge/ 知识

结构化产物由工具独占落盘（system/），不要手改存储文件；HYP 编号由工具自动分配（HYP-hunt<N>-H<M>），不要自己拟编号。落盘产物不要自行删除。
